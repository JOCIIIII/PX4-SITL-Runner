# A4VAI X500 for the inhouse SITL

SITL model of the A4VAI X500 test quad (Holybro X500 frame, Pixhawk 6X, 4S). PX4 v1.16 has an
X500 only for the new Gazebo (`Tools/simulation/gz/models/x500*`, airframe 4001_gz_x500); this
is a Gazebo Classic version whose dynamics come from the vehicle's own flight logs, like the
X8 (`scripts/px4/x8`). Plan: test on the X500, demonstrate on the X8.

| file | role |
|---|---|
| `x500.sdf.jinja` | Gazebo Classic model (PX4 renders it to `x500.sdf`); generated by `make_x500_model.py` |
| `make_x500_model.py` | every physical parameter (constants at the top) and how it is derived; geometry and meshes from PX4's gz x500, plugin wiring from the Classic iris, IMU/contact settings from the X8 |
| `2001_gazebo-classic_x500` | PX4 SITL airframe: the vehicle's own allocation, thrust model and gains/limits |
| `model.config` | model metadata |

`scripts/px4/build.sh` installs these (airframe 2001 registered next to the X8's 2000, the model
with the gz x500 meshes, and a one-time reconfigure so Gazebo renders `x500.sdf`). Rebuild after
a change with `./scripts/run.sh px4 build`. To regenerate the model:
`python3 scripts/px4/x500/make_x500_model.py <PX4>/Tools/simulation/gazebo-classic/sitl_gazebo-classic/models/iris/iris.sdf.jinja scripts/px4/x500/x500.sdf.jinja`

Select it with `SITL_AIRFRAME="x500"` in `envs/gazebo-classic.env` (C-Track harness: 7th
argument `x500`). The ROS2 apps treat it as a quad (PathFollowing `quad.yaml`, SUPER
`static_realgazebo.yaml`); the noclimb contact radius is its prop tips, 0.39 m.

## Sources

- Flight logs: `~/Desktop/00_Project/00_A4VAI/00_Development/00_Simulator/02_InhouseSim/flight-log/x500`,
  23 logs 2026-06-28 .. 2026-10-02 (the last two are the 3 m and 5 m altitude flights with video).
  Pixhawk 6X (FMU v6X), PX4 v1.16.0, `SYS_AUTOSTART 4001` (generic quad x), 4S, PWM 1100-1900,
  `THR_MDL_FAC 0`, all rate/attitude gains at PX4 defaults (`MC_AT_EN 1` but never applied).
  Flights are slow (< 3 m/s), offboard with takeoff/land.
- Geometry and meshes: PX4's gz `x500_base` (rotors at +-0.174 m, 11 in props).

## What the logs say (`scripts/dev/x8_sysid.py`, which handles any rotor count)

| quantity | value | logs |
|---|---|---|
| hover motor command u | 0.636 (0.620-0.691; PWM 1596-1653 us) | 5 flights with steady hover |
| thrust-to-weight | 2.5 (= 1 / 0.636^2 with thrust ~ u^2) | |
| roll / pitch rate plant K | 125 rad/s^2 per unit normalised torque (114-147) | 08_04_13, 08_10_27, 08_49_53 |
| motor lag | 21 ms (20-23; one pitch fit 40 ms), delay 20 ms | same |
| yaw rate plant K | 21 rad/s^2 per unit (19-23); lag at the fit's lower bound | same |
| horizontal drag | not identifiable (flights < 3 m/s) | |

PX4's allocation normalises the quad-x matrix: a unit roll/pitch torque command moves each motor
by +-0.707, a unit yaw command by +-1. With thrust = k (100 + 1000 u)^2 and the hover u fixed,
the torque per unit is 4 x 0.174 m x dT/du x 0.707, so the identified K sets Ixx (times the SITL
chain's measured factor, see Validation).

## Model values (MASS_TOTAL 2.0 kg, PX4's reference - the real all-up mass is not logged)

| | value |
|---|---|
| rotor speed | omega = 100 + 1000 u rad/s (iris channel mapping: armed idle 100; the vehicle's ESC idles at u = 0 too) |
| motorConstant k | 9.05e-6 (hover 4.90 N per rotor at 736 rad/s, max 10.95 N; thrust-to-weight 2.2) |
| Ixx = Iyy | 0.0364 kg m^2 (effective: the formula's value x 0.69, the SITL chain's measured torque factor) |
| Izz | 0.0674 kg m^2 (1.85 Ixx) |
| momentConstant / rotorInertia | 0.0182 m / 6.0e-5 kg m^2 (yaw gain and no lag, see Validation) |
| motor time constants | 21 ms up and down |
| rotorDragCoefficient | 7.47e-5 (0.11 1/s, the X8's value) |
| prop tips | 0.386 m from the centre |
| centre above ground at rest | 0.23 m (skid bars of the gz model) |

Hover command, thrust-to-weight, rate-plant gains and drag per mass are what the controller
sees, so the flight does not depend on the assumed mass; give the real mass to
`make_x500_model.py` when it is known and the inertias follow.

## Validation

`x8_step_test` (speed steps, 90 deg turn, altitude steps, +-40 deg zigzag) in plain Gazebo
(`FLY_PROFILE=gazebo-classic-sitl scripts/dev/fly_test.sh NAME 0 0 2.5 300 x8_step_test` with
`SITL_AIRFRAME="x500"`), then `x8_sysid.py` on the SITL log - the same estimates as on the vehicle:

| run | change | hover u | roll K / lag | pitch K / lag | yaw K / lag | drag |
|---|---|---|---|---|---|---|
| vehicle | 3 flights | 0.636 | 125-130 / 20-22 ms + 20 | 114-147 / 23-40 ms + 10-20 | 19-23 / ~0 (2-3 ms) | - |
| x500_step_a | omega = 1000 u, formula inertias | 0.540 | 84 / 29 ms | 90 / 26 ms | 18.6 / 69 ms | 0.11 |
| x500_step_b | idle 100 in k, inertia x 0.69, J_r 8e-6 | 0.640 | 115 / 22 ms + 10 | 128 / 25 ms + 10 | 22.2 / 69 ms + 20 | 0.11 |
| x500_step_c | J_r 1e-4 (physical) | 0.640 | 119 / 25 ms + 10 | 123 / 13 ms + 20 | 34.8 / ~0 | 0.11 |
| **x500_step_d** | **kQ and J_r x 21/34.8 (final)** | **0.642** | **119 / 25 ms + 10** | **123 / 13 ms + 20** | **18.9 / ~0** | **0.11** |

The final model matches the vehicle in hover command, roll/pitch rate plant and yaw (gain and
the absence of lag). Not checked: horizontal drag (the vehicle flew < 3 m/s), and flights in the
C-Track field.
